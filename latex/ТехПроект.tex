\section{Технический проект}

\subsection{Архитектура программной системы}

Разрабатываемая информационно-аналитическая система построена по архитектуре <<клиент--сервер>> с использованием REST-подхода.

Серверная часть реализована на языке программирования Python с использованием веб-фреймворка FastAPI и обеспечивает обработку HTTP-запросов, выполнение бизнес-логики, а также взаимодействие с базой данных PostgreSQL и файловым хранилищем документов.

Клиентская часть представляет собой веб-приложение, доступ к которому осуществляется через браузер. Взаимодействие между клиентом и сервером выполняется по протоколу HTTP с использованием формата JSON для обмена данными.

Архитектура системы включает следующие основные компоненты:
\begin{itemize}
	\item клиентское веб-приложение (пользовательский интерфейс);
	
	\item серверное приложение на базе FastAPI;
	
	\item систему управления базами данных PostgreSQL;
	
	\item файловое хранилище для загружаемых и сгенерированных документов;
	
	\item модуль анализа и проверки документов формата DOCX.
\end{itemize}

Логика работы системы организована следующим образом. Пользователь через веб-интерфейс выполняет действия (авторизация, загрузка документа, запуск проверки и другие операции), которые инициируют HTTP-запросы к серверной части приложения. Сервер выполняет обработку запроса, при необходимости обращается к базе данных и файловой системе, запускает процедуры анализа документа и возвращает результат клиенту.

Модуль проверки документов осуществляет анализ структуры и параметров оформления файлов формата DOCX, выявляет несоответствия установленным требованиям и формирует отчёт о найденных ошибках. При необходимости система дополнительно создаёт копию документа с визуальным выделением нарушений.

Все загружаемые документы сохраняются в файловой системе сервера, а информация о документах (путь к файлу, пользователь, результаты проверки и другие метаданные) хранится в базе данных PostgreSQL. Такой подход обеспечивает разделение хранения файлов и структурированных данных, а также повышает масштабируемость системы.

Для обеспечения безопасности и управления доступом используется механизм аутентификации пользователей на основе JWT-токенов. После успешной авторизации пользователь получает токен доступа, который используется при выполнении последующих запросов к API системы.

\subsection{Обоснование выбора технологии проектирования}

При выборе технологического стека разрабатываемой информационно-аналитической системы учитывались следующие критерии: поддержка обработки текстовых документов сложной структуры (учебников и учебных пособий), возможность расширения функциональности, удобство разработки, а также наличие инструментов для взаимодействия с документами формата DOCX и реализации веб-интерфейса.

\subsubsection{Язык программирования Python}

В качестве основного языка разработки выбран Python~3. Данный язык широко используется при создании информационных систем благодаря своей универсальности, высокой скорости разработки и наличию развитой экосистемы библиотек.

Выбор Python обусловлен необходимостью реализации алгоритмов автоматизированной проверки текстовых документов, а также построения серверной части веб-приложения. Язык предоставляет удобные средства для работы с файловой системой, обработки строковых данных и интеграции с внешними программными компонентами.

Для реализации функциональности системы используются следующие ключевые возможности и библиотеки Python:
\begin{enumerate}
	\item Высокая скорость разработки и читаемость кода.
	\item Наличие библиотек для работы с документами и веб-технологиями.
	\item Простота интеграции с внешними системами, включая Microsoft Word.
	\item Поддержка многослойной архитектуры приложения.
	\item Кроссплатформенность, позволяющая развертывать систему на различных операционных системах.
	\item Взаимодействие с текстовыми документами формата DOCX, включая их анализ и генерацию.
	\item Интеграция с текстовым процессором Microsoft Word посредством COM-интерфейса, что позволяет получать доступ к внутренней структуре документа (абзацы, стили, форматирование).
	\item Реализация веб-сервера с использованием современного фреймворка FastAPI.
	\item Работа с базой данных PostgreSQL через ORM-инструменты.
	\item Обработка HTTP-запросов и организация клиент-серверного взаимодействия.
\end{enumerate}

Таким образом, использование Python обеспечивает эффективную реализацию алгоритмов обработки учебных и учебно-методических документов, а также удобство разработки и сопровождения информационной системы.

\subsubsection{Веб-фреймворк FastAPI}

В качестве основного веб-фреймворка для реализации серверной части системы выбран FastAPI — современный высокопроизводительный фреймворк на языке Python, предназначенный для разработки REST API.

Выбор FastAPI обусловлен необходимостью обработки большого количества запросов, связанных с загрузкой, анализом и проверкой текстовых документов (учебников и учебных пособий), а также формированием отчётов и генерацией документов.

Фреймворк обеспечивает асинхронную обработку HTTP-запросов, что позволяет эффективно обрабатывать несколько пользовательских операций одновременно, включая:
\begin{itemize}
	\item загрузку документов в систему;
	\item запуск процедуры автоматической проверки;
	\item получение результатов анализа;
	\item скачивание обработанных файлов.
\end{itemize}

Одним из ключевых преимуществ FastAPI является встроенная поддержка валидации данных на основе аннотаций типов Python. Это позволяет автоматически проверять корректность входных данных (например, параметров запроса или метаданных документа), снижая вероятность ошибок на этапе обработки.

Механизм маршрутизации FastAPI связывает URL-адреса с функциями-обработчиками (endpoint). Например:
\begin{enumerate}
	\item Запрос на загрузку документа направляется к обработчику загрузки файла.
	\item Запрос на запуск проверки — к модулю анализа документа.
	\item Запрос на получение результата — к обработчику формирования отчёта.
\end{enumerate}

Дополнительным преимуществом является автоматическая генерация интерактивной документации, что упрощает тестирование и отладку системы.

Таким образом, использование FastAPI позволяет реализовать масштабируемую и производительную серверную часть системы, обеспечивающую обработку учебных и учебно-методических документов в многопользовательском режиме.

\subsubsection{СУБД PostgreSQL}

В качестве системы управления базами данных выбрана PostgreSQL — современная объектно-реляционная СУБД, обеспечивающая высокую надёжность, производительность и поддержку сложных структур данных.

Выбор PostgreSQL обусловлен необходимостью хранения и обработки различных типов данных, используемых в информационно-аналитической системе редакционно-издательского отдела. К ним относятся:
\begin{itemize}
	\item учетные записи пользователей и их роли;
	\item информация о загруженных документах;
	\item результаты автоматизированной проверки;
	\item отчёты об ошибках и история обработки документов;
	\item служебные данные системы.
\end{itemize}

PostgreSQL обеспечивает поддержку ссылочной целостности данных за счёт использования внешних ключей и каскадных операций. Это позволяет автоматически поддерживать согласованность данных при удалении связанных сущностей, таких как документы и результаты их проверки.

Использование транзакций гарантирует целостность данных при выполнении операций добавления, изменения и удаления. В случае возникновения ошибок возможен откат изменений, что исключает появление неконсистентных данных.

Для взаимодействия с базой данных применяется ORM-технология, позволяющая работать с данными на уровне объектов приложения. Это упрощает разработку, повышает читаемость кода и снижает вероятность ошибок при формировании SQL-запросов.

Сервер базы данных функционирует как отдельный компонент системы и взаимодействует с серверной частью приложения по сети. Такой подход обеспечивает:
\begin{itemize}
	\item возможность масштабирования системы;
	\item одновременную работу нескольких пользователей;
	\item централизованное хранение данных;
	\item повышение отказоустойчивости.
\end{itemize}

Для повышения производительности используется механизм пула соединений с базой данных, позволяющий переиспользовать уже установленные подключения. Это снижает накладные расходы на установление соединений и обеспечивает эффективную обработку параллельных запросов.

Таким образом, PostgreSQL обеспечивает надёжное хранение данных и эффективную работу системы при обработке учебных и учебно-методических документов.

\subsubsection{Средства работы с документами}

Ключевым аспектом разрабатываемой системы является обработка текстовых документов формата DOCX, содержащих учебники и учебные пособия. Для реализации данной функциональности используются специализированные средства работы с документами Microsoft Word.

Основной механизм анализа документов реализован с использованием COM-интерфейса Microsoft Word. Данный подход позволяет работать с документом на уровне его внутренней структуры, включая:
\begin{itemize}
	\item доступ к абзацам, разделам и стилям оформления;
	\item получение параметров форматирования (шрифт, размер, интервалы, отступы);
	\item определение структуры документа (заголовки, списки, таблицы);
	\item модификацию документа (выделение ошибок, добавление комментариев).
\end{itemize}

Использование COM-интерфейса обеспечивает более точный и полный анализ документов по сравнению с альтернативными библиотеками, так как позволяет учитывать особенности форматирования, применяемые в текстовом процессоре Microsoft Word.

Для генерации документов (например, титульных листов) используется библиотека python-docx. Она позволяет программно создавать DOCX-файлы, задавать структуру документа и управлять параметрами форматирования.

Таким образом, совокупное использование COM-интерфейса и библиотеки python-docx обеспечивает как анализ, так и генерацию учебных и учебно-методических документов.

\subsubsection{Прочие библиотеки и инструменты}

В процессе разработки информационно-аналитической системы используются дополнительные библиотеки и инструменты, обеспечивающие реализацию вспомогательной функциональности.

Для организации аутентификации и авторизации пользователей применяются механизмы на основе JWT (JSON Web Token), обеспечивающие безопасную передачу данных между клиентом и сервером.

Логирование работы системы реализовано с использованием стандартного модуля Python logging. В журнал событий записываются:
\begin{itemize}
	\item действия пользователей (загрузка документов, запуск проверки);
	\item ошибки и исключительные ситуации;
	\item служебные сообщения системы.
\end{itemize}

Это позволяет выполнять мониторинг работы системы и упрощает процесс отладки.

Для запуска серверной части используется ASGI-сервер Uvicorn, обеспечивающий высокую производительность и поддержку асинхронной обработки запросов.

Дополнительно применяются средства работы с файловой системой Python для хранения загруженных документов, формирования временных файлов и организации архива обработанных материалов.

Таким образом, используемые библиотеки и инструменты обеспечивают стабильную и безопасную работу системы, а также поддержку основных процессов обработки учебных и учебно-методических документов.

\subsection{Описание серверной части}

Серверная часть информационно-аналитической системы является основным компонентом, реализующим бизнес-логику обработки учебных и учебно-методических изданий. Именно на серверной стороне выполняются операции анализа документов, проверки параметров форматирования, генерации титульных листов, формирования отчётов и взаимодействия с базой данных.

Архитектура серверной части построена на основе веб-фреймворка FastAPI, обеспечивающего обработку HTTP-запросов, маршрутизацию, взаимодействие между компонентами системы и предоставление REST API для клиентской части приложения.

Взаимодействие клиента и сервера осуществляется по протоколу HTTP в формате запрос--ответ. Пользователь через веб-интерфейс отправляет запросы на загрузку документов, запуск проверки, генерацию титульных листов и получение результатов обработки. Сервер принимает запросы, выполняет необходимую обработку данных и возвращает результаты пользователю.

Серверная часть реализует REST API, предназначенный для:
\begin{itemize}
	\item аутентификации и авторизации пользователей;
	\item загрузки документов формата DOCX;
	\item запуска процедуры автоматизированной проверки;
	\item получения результатов анализа;
	\item генерации титульных листов;
	\item скачивания сформированных отчётов и обработанных документов.
\end{itemize}

Ключевым компонентом серверной части является модуль обработки документов, реализующий алгоритмы анализа учебников и учебных пособий. Проверка документов осуществляется посредством взаимодействия с текстовым процессором Microsoft Word через COM-интерфейс, что позволяет получать доступ к внутренней структуре DOCX-документа:
\begin{itemize}
	\item абзацам;
	\item разделам;
	\item стилям оформления;
	\item параметрам страницы;
	\item таблицам и спискам;
	\item элементам форматирования текста.
\end{itemize}

В процессе анализа выполняется последовательная проверка параметров форматирования документа на соответствие установленным требованиям. Результатом обработки является структурированный отчёт, содержащий сведения о выявленных ошибках, их типах и расположении в документе.

Дополнительно серверная часть реализует механизм визуальной разметки документов. На основе результатов проверки формируется копия исходного файла, содержащая выделение ошибок и комментарии, упрощающие процесс исправления нарушений оформления.

Отдельным компонентом серверной части является модуль генерации титульных листов. Генерация осуществляется на основе шаблонного подхода: пользователь вводит необходимые параметры через веб-интерфейс, после чего сервер формирует готовый DOCX-документ с автоматически заполненными страницами титульной части учебного издания.

Для хранения данных используется система управления базами данных PostgreSQL. В базе данных сохраняются:
\begin{itemize}
	\item данные пользователей;
	\item сведения о кафедрах и факультетах;
	\item информация о загруженных документах;
	\item результаты проверок;
	\item данные аутентификации и refresh-токены;
	\item служебная информация системы.
\end{itemize}

Взаимодействие с базой данных реализовано с использованием ORM SQLAlchemy, обеспечивающей объектно-реляционное отображение данных и упрощающей выполнение операций чтения, записи и обновления информации.

Для обеспечения безопасности доступа к системе используется механизм JWT-аутентификации (JSON Web Token). После успешной авторизации сервер формирует access- и refresh-токены, обеспечивающие безопасное взаимодействие клиента с защищёнными ресурсами системы.

Серверная часть включает несколько взаимосвязанных модулей:
\begin{itemize}
	\item модуль маршрутизации и обработки HTTP-запросов;
	\item модуль аутентификации и авторизации;
	\item модуль проверки учебных изданий;
	\item модуль генерации титульных листов;
	\item модуль формирования отчётов;
	\item модуль взаимодействия с базой данных.
\end{itemize}

Взаимодействие модулей построено по принципу разделения ответственности, при котором каждый компонент выполняет строго определённые функции. Такой подход обеспечивает модульность архитектуры, упрощает сопровождение системы и позволяет расширять функциональность без изменения существующих компонентов.

\subsection{Описание API}

Взаимодействие клиентской части с сервером реализовано посредством REST API, построенного на основе веб-фреймворка FastAPI. API обеспечивает обмен данными между пользовательским интерфейсом и внутренними компонентами системы, а также предоставляет набор endpoint-обработчиков для выполнения основных операций.

Обмен данными осуществляется по протоколу HTTP. Для передачи структурированных данных используется формат JSON, а загрузка документов выполняется с использованием формата \texttt{multipart/form-data}.

Основными функциями API являются:
\begin{itemize}
	\item обработка HTTP-запросов;
	\item маршрутизация запросов между компонентами системы;
	\item валидация входных данных;
	\item формирование HTTP-ответов;
	\item обработка ошибок и исключений;
	\item обеспечение взаимодействия клиентской части с серверной логикой.
\end{itemize}

Архитектура API построена по модульному принципу. Для разделения функциональности используются отдельные маршрутизаторы (routers), отвечающие за конкретные подсистемы приложения.

В системе реализованы следующие основные маршрутизаторы:
\begin{enumerate}
	\item auth — модуль аутентификации и авторизации пользователей.
	\item checker — модуль загрузки и проверки документов.
	\item title\_page — модуль генерации титульных листов.
	\item statistics — модуль получения статистических данных.
	\item admin — административный модуль управления системой.
\end{enumerate}

Маршрутизатор auth обеспечивает:
\begin{itemize}
	\item регистрацию пользователей;
	\item вход в систему;
	\item обновление access-токенов;
	\item завершение пользовательской сессии;
	\item получение информации о текущем пользователе.
\end{itemize}

Маршрутизатор checker предназначен для:
\begin{itemize}
	\item загрузки документов формата DOCX;
	\item запуска процедуры проверки;
	\item получения результатов анализа;
	\item скачивания отчётов;
	\item получения размеченных документов.
\end{itemize}

Маршрутизатор title\_page реализует:
\begin{itemize}
	\item приём параметров генерации;
	\item формирование DOCX-документов;
	\item выдачу готовых титульных листов пользователю.
\end{itemize}

Маршрутизатор statistics обеспечивает получение:
\begin{itemize}
	\item статистики проверок;
	\item сведений об ошибках;
	\item данных об активности пользователей.
\end{itemize}

Маршрутизатор admin предоставляет административные функции:
\begin{itemize}
	\item управление пользователями;
	\item изменение ролей;
	\item просмотр журналов действий;
	\item управление справочными данными системы.
\end{itemize}

FastAPI автоматически выполняет:
\begin{itemize}
	\item сопоставление URL-адресов с endpoint-функциями;
	\item проверку типов входных данных;
	\item сериализацию и десериализацию объектов;
	\item формирование JSON-ответов;
	\item обработку ошибок валидации.
\end{itemize}

При поступлении запроса сервер выполняет маршрутизацию и передаёт управление соответствующему endpoint-обработчику. Далее запрос направляется в сервисный модуль системы, реализующий необходимую бизнес-логику. После завершения обработки формируется HTTP-ответ, возвращаемый клиентской части.

Дополнительно API реализует централизованную обработку исключений. В случае возникновения ошибок сервер формирует структурированный ответ, содержащий код ошибки и описание проблемы.

Использование REST API обеспечивает модульность, масштабируемость и возможность дальнейшего расширения функциональности системы.

\subsection{Модуль маршрутизации и обработки HTTP-запросов}

Модуль маршрутизации и обработки HTTP-запросов является центральным компонентом серверной части информационно-аналитической системы. Данный модуль обеспечивает взаимодействие между клиентской частью приложения и внутренними сервисами серверной части.

Реализация модуля основана на веб-фреймворке FastAPI, обеспечивающем обработку HTTP-запросов, маршрутизацию и вызов соответствующих обработчиков.

Основными задачами модуля являются:
\begin{itemize}
	\item приём HTTP-запросов;
	\item распределение запросов между серверными компонентами;
	\item вызов сервисных модулей;
	\item управление потоком обработки запросов;
	\item формирование HTTP-ответов.
\end{itemize}

Архитектура маршрутизации построена по модульному принципу. Для разделения логики используются отдельные маршрутизаторы (routers), связанные с функциональными подсистемами приложения.

Каждый маршрутизатор содержит набор endpoint-обработчиков, реализующих отдельные операции системы.

Модуль маршрутизации взаимодействует:
\begin{itemize}
	\item с модулем аутентификации;
	\item с модулем проверки документов;
	\item с модулем генерации титульных листов;
	\item с модулем формирования отчётов;
	\item с модулем работы с базой данных.
\end{itemize}

После получения HTTP-запроса FastAPI выполняет маршрутизацию запроса и передаёт управление соответствующему обработчику. Далее запрос направляется в сервисный слой системы, реализующий бизнес-логику.

Результатом работы модуля является сформированный HTTP-ответ, возвращаемый клиентской части приложения.

Использование модульной системы маршрутизации позволяет:
\begin{itemize}
	\item разделить ответственность между компонентами;
	\item упростить сопровождение серверной части;
	\item обеспечить масштабируемость приложения;
	\item упростить расширение функциональности системы.
\end{itemize}

\subsection{Модуль аутентификации и авторизации}

Модуль аутентификации и авторизации предназначен для обеспечения безопасного доступа пользователей к функциям информационно-аналитической системы. Данный модуль реализует механизмы идентификации пользователей, проверки прав доступа и управления пользовательскими сессиями.

В разработанной системе аутентификация реализована на основе технологии JWT (JSON Web Token). Использование токен-ориентированного подхода позволяет отказаться от хранения пользовательских сессий на сервере и обеспечивает безопасное взаимодействие между клиентской и серверной частями приложения.

Модуль аутентификации включает следующие основные компоненты:
\begin{enumerate}
	\item \texttt{auth.py} — содержит маршруты авторизации и обновления токенов.
	
	\item \texttt{auth\_service.py} — реализует бизнес-логику аутентификации пользователей.
	
	\item \texttt{refresh\_token.py} — отвечает за создание, хранение и отзыв refresh-токенов.
	
	\item \texttt{security.py} — реализует функции генерации JWT-токенов, хеширования и проверки паролей.
	
	\item \texttt{dependencies.py} — содержит зависимости FastAPI для проверки авторизации и прав доступа.
\end{enumerate}

\subsubsection{Процесс аутентификации пользователя}

Процесс входа пользователя в систему включает следующие этапы:
\begin{enumerate}
	\item Пользователь вводит логин и пароль через веб-интерфейс.
	
	\item Клиентская часть отправляет HTTP-запрос на серверный маршрут авторизации.
	
	\item Модуль \texttt{auth.py} принимает запрос и передаёт данные в сервис аутентификации.
	
	\item Компонент \texttt{auth\_service.py} выполняет:
	\begin{itemize}
		\item поиск пользователя в базе данных;
		\item проверку корректности пароля;
		\item определение роли пользователя.
	\end{itemize}
	
	\item При успешной проверке создаются:
	\begin{itemize}
		\item access token;
		\item refresh token.
	\end{itemize}
	
	\item Access token возвращается клиенту для последующего доступа к API.
	
	\item Refresh token сохраняется в базе данных и используется для обновления access token без повторного ввода пароля.
\end{enumerate}

\subsubsection{JWT-токены}

Для реализации механизма авторизации используются два типа токенов:
\begin{itemize}
	\item \textbf{Access token} — краткоживущий токен, используемый для доступа к защищённым маршрутам API;
	
	\item \textbf{Refresh token} — долгоживущий токен, предназначенный для обновления access token.
\end{itemize}

JWT-токены содержат зашифрованную информацию о пользователе:
\begin{itemize}
	\item идентификатор пользователя;
	\item роль пользователя;
	\item время создания токена;
	\item срок действия токена.
\end{itemize}

Генерация и проверка JWT выполняется модулем \texttt{security.py}. Для повышения безопасности токены подписываются секретным ключом с использованием криптографического алгоритма.

\subsubsection{Хеширование паролей}

Пароли пользователей не хранятся в открытом виде. Перед сохранением в базе данных выполняется их хеширование с использованием криптографических функций.

Модуль \texttt{security.py} реализует:
\begin{itemize}
	\item генерацию хеша пароля;
	\item проверку соответствия введённого пароля сохранённому хешу.
\end{itemize}

Данный подход обеспечивает защиту пользовательских данных даже при компрометации базы данных.

\subsubsection{Роли пользователей и разграничение прав доступа}

В системе реализована ролевая модель доступа. Каждому пользователю назначается определённая роль, определяющая набор доступных функций.

В системе предусмотрены следующие основные роли:
\begin{enumerate}
	\item Администратор.
	\item Сотрудник редакционно-издательского отдела.
	\item Обычный пользователь.
\end{enumerate}

Проверка прав доступа выполняется с использованием зависимостей FastAPI, реализованных в модуле \texttt{dependencies.py}.

При обращении к защищённому маршруту:
\begin{enumerate}
	\item Выполняется проверка наличия access token.
	\item Производится декодирование JWT.
	\item Определяется роль пользователя.
	\item Проверяется наличие необходимых прав доступа.
\end{enumerate}

При отсутствии необходимых прав сервер возвращает сообщение об ошибке авторизации.

\subsubsection{Хранение refresh token}

Refresh token сохраняются в таблице \texttt{RefreshToken} базы данных. Для каждого токена хранятся:
\begin{itemize}
	\item идентификатор пользователя;
	\item хеш токена;
	\item дата создания;
	\item срок действия;
	\item информация об устройстве и IP-адресе;
	\item признак отзыва токена.
\end{itemize}

Использование отдельной таблицы refresh token позволяет:
\begin{itemize}
	\item завершать пользовательские сессии;
	\item отзывать токены при выходе пользователя;
	\item контролировать активные подключения;
	\item повышать безопасность системы.
\end{itemize}

\subsubsection{Dependencies и middleware}

Для защиты маршрутов FastAPI используются специальные зависимости (dependencies), автоматически выполняющие проверку авторизации перед вызовом обработчика запроса.

Dependencies обеспечивают:
\begin{itemize}
	\item получение текущего пользователя;
	\item проверку JWT-токена;
	\item проверку роли пользователя;
	\item ограничение доступа к административным маршрутам.
\end{itemize}

Дополнительно в системе могут использоваться middleware-компоненты, выполняющие:
\begin{itemize}
	\item логирование запросов;
	\item контроль времени обработки;
	\item обработку ошибок авторизации;
	\item централизованную обработку исключений.
\end{itemize}

Таким образом, модуль аутентификации и авторизации обеспечивает безопасный доступ пользователей к функциональности системы, реализует разграничение прав доступа и поддерживает механизм защищённых пользовательских сессий.

\subsection{Модуль проверки документов}

Одним из ключевых компонентов серверной части информационно-аналитической системы является модуль проверки учебных изданий, реализующий автоматизированный анализ учебников и учебных пособий на соответствие установленным требованиям оформления.

Основная логика проверки реализована в модуле \texttt{checker.py}. Данный модуль выполняет структурный анализ документов формата DOCX, извлечение параметров форматирования и формирование результатов проверки.

Основной задачей модуля является автоматизация процесса контроля оформления учебных изданий, что позволяет существенно сократить время проверки документов и уменьшить количество ошибок, связанных с человеческим фактором.

\subsubsection{Основные функции модуля проверки}

Модуль проверки обеспечивает выполнение следующих функций:
\begin{enumerate}
	\item Загрузка и открытие документа формата DOCX.
	
	\item Анализ структуры документа.
	
	\item Последовательный обход абзацев и элементов документа.
	
	\item Проверка параметров форматирования.
	
	\item Выявление и классификация ошибок.
	
	\item Формирование отчёта о проверке.
	
	\item Создание копии документа с визуальной разметкой ошибок.
\end{enumerate}

\subsection{Модуль генерации титульных листов}

Одним из компонентов серверной части информационно-аналитической системы является модуль генерации титульных листов, предназначенный для автоматического формирования титульной части документов в соответствии с установленными требованиями оформления.

Основная логика реализована в следующих компонентах:
\begin{enumerate}
	\item \texttt{title\_page.py} — обработка API-запросов.
	\item \texttt{title\_page\_generator.py} — генерация DOCX-документов.
	\item \texttt{schemas/title\_page.py} — валидация входных данных.
\end{enumerate}

\subsubsection{Назначение модуля}

Модуль предназначен для:
\begin{enumerate}
	\item Автоматизации подготовки титульных листов.
	\item Исключения ошибок ручного форматирования.
	\item Обеспечения единообразного оформления документов.
	\item Сокращения времени подготовки документации.
\end{enumerate}

\subsubsection{Генерация DOCX-документов}

В основе работы модуля используется шаблонный подход. После проверки пользовательских данных система автоматически формирует DOCX-документ с применением установленных параметров форматирования.

В процессе генерации:
\begin{itemize}
	\item создаётся структура документа;
	\item выполняется размещение текстовых блоков;
	\item применяются параметры форматирования;
	\item сохраняется итоговый DOCX-файл.
\end{itemize}

\subsubsection{Форматирование титульного листа}

При генерации документа автоматически контролируются:
\begin{itemize}
	\item параметры шрифта;
	\item межстрочные интервалы;
	\item выравнивание текста;
	\item размеры полей страницы;
	\item расположение текстовых блоков.
\end{itemize}

Таким образом, модуль обеспечивает автоматизированное создание титульных листов и снижает вероятность ошибок оформления.

\subsection{Модуль формирования отчётов}

Модуль формирования отчётов предназначен для автоматического создания PDF-документов по результатам проверки учебных изданий. Основная логика реализована в файле \texttt{pdf\_report.py}.

Модуль получает результаты анализа документа, выполняет обработку выявленных ошибок и формирует структурированный PDF-отчёт.

\subsubsection{Основные функции модуля}

Основные функции модуля:
\begin{itemize}
	\item формирование PDF-отчётов;
	\item группировка ошибок по типам;
	\item сортировка нарушений;
	\item отображение статистики проверки;
	\item визуализация результатов анализа.
\end{itemize}

При генерации используются:
\begin{itemize}
	\item сведения о документе;
	\item дата и время проверки;
	\item список обнаруженных ошибок;
	\item информация о страницах и абзацах с нарушениями.
\end{itemize}

\subsubsection{Группировка ошибок}

Для уменьшения объёма отчёта реализован механизм агрегации ошибок. Однотипные нарушения объединяются в диапазоны и отображаются как единая запись.

Это позволяет:
\begin{itemize}
	\item сократить объём отчёта;
	\item упростить анализ результатов проверки;
	\item повысить читаемость документа.
\end{itemize}

\subsubsection{Структура PDF-отчёта}

Итоговый отчёт включает:
\begin{enumerate}
	\item Информацию о документе.
	\item Статистику проверки.
	\item Список выявленных ошибок.
	\item Итоговые результаты анализа.
\end{enumerate}

В процессе генерации выполняется оформление заголовков, таблиц, разделов и нумерации страниц.

\subsubsection{Взаимодействие с компонентами системы}

Модуль взаимодействует со следующими компонентами:
\begin{itemize}

	\item базой данных;
	\item REST API;
	\item модулем визуальной разметки.

Сформированный PDF-документ сохраняется на сервере и становится доступным пользователю через веб-интерфейс системы.

\subsection{Форматы данных}

Обмен данными между клиентской и серверной частями информационно-аналитической системы осуществляется по протоколу HTTP в формате запрос--ответ. Пользователь через веб-интерфейс выполняет загрузку учебных изданий, запуск проверки документов, генерацию титульных листов и получение результатов обработки.

Взаимодействие с REST API серверной части реализовано с использованием формата JSON. Данный формат применяется при передаче служебной информации, параметров запросов, результатов проверки и ответов API. Использование JSON обеспечивает универсальность обмена данными и упрощает взаимодействие клиентской и серверной частей системы.

При загрузке документов используется формат \texttt{multipart/form-data}, обеспечивающий передачу бинарных файлов. Данный механизм применяется при отправке учебников и учебных пособий в формате DOCX на сервер для последующего анализа.

Основным форматом обрабатываемых документов является \textbf{DOCX}. Формат DOCX используется для представления учебников и учебных пособий и позволяет выполнять программный доступ к структуре документа, включая:
\begin{itemize}
	\item абзацы;
	\item стили оформления;
	\item разделы;
	\item таблицы;
	\item параметры страниц;
	\item элементы форматирования.
\end{itemize}

Результаты обработки документов представляются в нескольких форматах:
\begin{enumerate}
	\item JSON-структуры, содержащие сведения о результатах проверки, найденных ошибках и служебной информации.
	
	\item PDF-отчёты, формируемые модулем генерации отчётов и содержащие структурированную информацию о выявленных нарушениях оформления.
	
	\item DOCX-файлы с визуальной разметкой ошибок и комментариями.
	
	\item Сгенерированные титульные листы учебников и учебных пособий в формате DOCX.
\end{enumerate}

Взаимодействие с базой данных осуществляется посредством ORM SQLAlchemy. Данные сохраняются в реляционном виде в таблицах пользователей, факультетов, кафедр, учебных материалов и токенов обновления.

Файлы учебных изданий хранятся в файловой системе сервера, а в базе данных сохраняются их метаданные, включая:
\begin{itemize}
	\item название документа;
	\item путь к файлу;
	\item дату загрузки;
	\item сведения о пользователе;
	\item статус обработки.
\end{itemize}

Журналирование работы системы выполняется в текстовом формате с использованием временных меток и уровней событий (\texttt{INFO}, \texttt{WARNING}, \texttt{ERROR}). Журнал содержит сведения о действиях пользователей, этапах обработки документов и возникающих ошибках, что позволяет выполнять мониторинг работы системы и упрощает процесс отладки.

Таким образом, используемые форматы данных обеспечивают корректную передачу, обработку и хранение информации в рамках информационно-аналитической системы автоматизированной проверки учебников и учебных пособий.
